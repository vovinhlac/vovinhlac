## How I work

I keep portfolio engineering work reviewable through the same workflow I would use on a team:

`Issue / acceptance criteria` → `focused branch` → `atomic commits` → `pull request` → `CI checks` → `merge`

Branch names use clear intent such as `feat/`, `fix/`, `refactor/`, `perf/`, `security/`, `ci/`, `docs/`, and `chore/`. Commit subjects follow Conventional Commit-style prefixes so history stays easy to scan and revert.
